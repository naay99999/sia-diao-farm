# Security & Performance Audit — 2026-10-31

Scope: Laravel backend (routes, middleware, controllers, form requests, `app/Support`, MCP server and OAuth), Docker/Caddy deployment, dependencies (`composer.lock`, `package-lock.json`) and the PostgreSQL schema. Commit audited: `e1005ec`.

This follows the [2026-10-26 performance audit](2026-10-26-performance-audit.md). All ten items from that audit are fixed and covered by tests (`QueryPlanTest`, `PhotoDeliveryTest` and others), so this report covers only new or still-open issues.

## Summary

The app's own code is in good shape. Authentication, deactivation, CSRF, file uploads, redirects and raw SQL are all handled correctly (see [What is already done well](#what-is-already-done-well)). The real risks are in three places:

1. **Outdated dependencies** with published advisories, one of which can be triggered by anyone on the internet.
2. **The MCP OAuth flow** accepts any redirect domain, and its consent screen shows only the name the client chose for itself. That makes it possible to phish a family member into giving a stranger a one-year read/write token.
3. **Production hardening**: no security headers, the session cookie is not forced to `Secure`, and tokens last a year.

On performance, the move to PostgreSQL left a few foreign keys without indexes, and the biggest remaining gain is running PHP in worker mode.

## Security findings

### S1. Vulnerable Composer dependencies (High)

`composer audit` reports these advisories for production packages:

| Package | Locked | Advisory | Reachable here? |
|---------|--------|----------|-----------------|
| `symfony/http-foundation` | v8.1.0 | CVE-2026-108082 (high): ReDoS in `HeaderUtils::split()` through the `Cache-Control` **request** header | **Yes.** Any unauthenticated request can send that header, so a few requests can tie up PHP threads. |
| `laravel/framework` | v13.17.0 | CVE-2026-114509 (critical): TokenGuard bypass with non-string credentials | No. The `api` guard uses the `passport` driver, not `token`. Upgrade anyway. |
| `laravel/framework` | v13.17.0 | CVE-2026-114508 (medium): relationship inclusion can trigger unauthorized deletes; CVE-2026-102279 (low): XSS on the debug page | Unlikely (`APP_DEBUG=false` in production). |
| `guzzlehttp/guzzle` | 7.12.3 | 6 advisories (1 high): host-check bypass, cookie scope, `Proxy-Authorization` leaks | Low. The only outbound calls are Passport and the `uncompromised()` password check. |
| `league/commonmark` | 2.8.2 | 12 advisories (DoS, XSS in `AttributesExtension`) | Low. The app does not render user Markdown; only Laravel's mail templates use it. |
| `symfony/mime` | v8.1.0 | CVE-2026-45070 (medium): email header injection | Low (mail goes to the log). |
| `league/flysystem` | 3.35.1 | CVE-2026-102601 (low): path normalizer bypass | Low. Photo paths are generated by `putFile()`, not by users. |

`symfony/yaml` (high) is also reported, but only dev packages (`laravel/sail`, `laravel/roster`) use it.

**Recommendation:** `composer update` (patch and minor versions are enough for all of the above), then run the full test suite. Add `composer audit` to the CI workflow so new advisories fail the build.

### S2. MCP OAuth: any redirect domain is accepted, and the consent screen hides it (High)

`routes/ai.php` registers `Mcp::oauthRoutes()`, which includes open dynamic client registration (`POST /oauth/register`). There is no `config/mcp.php`, so the package default applies:

```php
'redirect_domains' => ['*'],
```

Anyone can register a client with **any name** (for example "Claude") and **any redirect URI**. The consent screen `resources/views/mcp/authorize.blade.php` shows `{{ $client->name }}` and the user's email, but not where the code will be sent.

Attack: an outsider registers a client called "Claude" with redirect `https://attacker.example/cb`, then sends a family member the `/oauth/authorize?...` link ("reconnect Claude to the farm"). The member is already logged in, sees "อนุญาต Claude", and approves. The attacker receives a code, exchanges it, and gets a token that can read and write the whole farm for a year (see S3). Registration is rate-limited (10 per minute), but that does not prevent this attack.

**Recommendation:**

1. Publish the config (`php artisan vendor:publish --tag=mcp-config`) and limit redirect domains to the clients the farm actually uses:
   ```php
   'redirect_domains' => array_filter([
       'https://claude.ai',
       'https://claude.com',
       env('APP_ENV') === 'local' ? 'http://localhost' : null,
   ]),
   ```
2. On the consent screen, show the redirect host under the client name (for example, "ข้อมูลจะถูกส่งไปที่ claude.ai"), so a mismatched name is visible.
3. Add a feature test: registration with a non-allowlisted redirect returns `400 invalid_redirect_uri`.

### S3. Long-lived, all-powerful OAuth tokens (Medium)

Passport defaults are in effect (`Passport::tokensExpireIn()` and `refreshTokensExpireIn()` are never called), so **access tokens and refresh tokens are both valid for 1 year**. The single `mcp:use` scope grants every tool, including `delete_record`. Deactivating a member revokes their tokens (`AiConnections::revokeAll`), but a token leaked from a still-active member stays usable for a year.

**Recommendation:** in `AppServiceProvider::configurePassport()`:

```php
Passport::tokensExpireIn(CarbonInterval::hours(1));
Passport::refreshTokensExpireIn(CarbonInterval::days(30));
```

MCP clients refresh automatically, so users notice nothing. A separate read-only scope is optional and can wait until there is a client that needs only read access.

### S4. No security headers (Medium)

Neither `docker/Caddyfile` nor any middleware sets `Strict-Transport-Security`, `X-Frame-Options` / CSP `frame-ancestors`, `X-Content-Type-Options` or `Referrer-Policy`. The concrete risk is **clickjacking**: the OAuth approve page (one button) and the settings pages can be framed by another site. Traefik may add some headers, but nothing in the repo configures that.

**Recommendation:** add this to the site block in `docker/Caddyfile`:

```caddy
header {
	Strict-Transport-Security "max-age=31536000; includeSubDomains"
	X-Frame-Options "DENY"
	Content-Security-Policy "frame-ancestors 'none'"
	X-Content-Type-Options "nosniff"
	Referrer-Policy "strict-origin-when-cross-origin"
	-Server
}
```

A full script CSP can come later. Inertia and the inline theme script in `app.blade.php` would need nonces (`Vite::useCspNonce()`).

### S5. Session cookie not forced to `Secure` (Medium)

`config/session.php` reads `'secure' => env('SESSION_SECURE_COOKIE')`, and neither `.env.example` nor `compose.yaml` sets it. When it is `null`, Laravel does not add the `Secure` flag, so the session cookie could be sent over plain HTTP (for example, on a first `http://` request before Traefik redirects).

**Recommendation:** add `SESSION_SECURE_COOKIE: "true"` to the `environment` block in `compose.yaml`, next to `APP_DEBUG: "false"`, so a copied `.env` cannot turn it off.

### S6. Password change or reset leaves other sessions and AI tokens alive (Low)

- `ProfileController::updatePassword` changes the password but does not log out other devices.
- `MemberController::resetPassword` (the owner resets a member's password) does not end that member's sessions or revoke their Claude connections. If the reset is because the account was compromised, the attacker stays logged in.

**Recommendation:** after a self-service change, call `Auth::logoutOtherDevices($request->password)`, or delete the user's other rows in `sessions` (the session driver is `database`). After an owner reset, delete the member's `sessions` rows and call `AiConnections::revokeAll($user->id)`. Add a test for each.

### S7. npm advisories and lockfile drift (Low)

`npm audit` (against `package-lock.json`) reports 11 advisories, including 1 critical (`shell-quote` through `concurrently`) and `vite` 8.1.0 (dev-server file disclosure and cross-origin script execution). All of these are **build or dev-server tools**. None ship in `public/build`, so production users are not exposed. The risk is to the developer machine while `npm run dev` runs.

In addition, local `node_modules` is installed by **pnpm** (it resolves `vite` 8.3.5), but the `Dockerfile` runs `npm ci` against `package-lock.json` (`vite` 8.1.0). Production assets are therefore built from a different dependency tree than the one tested locally.

**Recommendation:** pick one package manager. With npm, run `npm audit fix`, commit the lockfile and remove the pnpm install. With pnpm, commit `pnpm-lock.yaml` and switch the Dockerfile to `pnpm install --frozen-lockfile`. Add `npm audit --omit=dev` to CI.

### S8. Unbounded free-text fields (Low)

Every `notes` rule in `app/Http/Requests/Farm/*` is `['nullable', 'string']` with no `max`. Any logged-in member, or an MCP client, can store multi-megabyte notes (limited only by `post_max_size = 30M`). Those notes are then sent in every timeline, records page and MCP response. This is mostly a robustness issue, since only trusted accounts can write.

**Recommendation:** add `max:2000` (or similar) to the `notes` rules in the form requests and the MCP tool validation.

### S9. `trustProxies(at: '*')` (Info)

`bootstrap/app.php` trusts every proxy. This is safe today because `compose.yaml` only `expose`s port 80 on `dokploy-network`, so all traffic arrives through Traefik. If the port is ever published directly, a client could spoof `X-Forwarded-For` and get a new login throttle key (`email|ip`) on every request, which bypasses brute-force protection.

**Recommendation:** leave a comment next to `trustProxies` explaining this assumption, or pin it to the Docker network's subnet.

## Performance findings

### P1. PHP boots Laravel on every request (Medium)

`docker/Caddyfile` uses `php_server` in FrankenPHP's classic mode. OPcache is on with `validate_timestamps=0`, and `php artisan optimize` runs on start. Even so, every request rebuilds the container, loads providers, connects to PostgreSQL, and so on. On small pages, the bootstrap is usually most of the response time.

**Recommendation:** run FrankenPHP in worker mode through Laravel Octane (`laravel/octane`, `php artisan octane:frankenphp`). This is a new dependency, so it needs your approval. Check before switching: no static or singleton state that leaks between requests. `Context` is already scoped per request in `FarmWriteTool`, and `Date::use()` and `Model::preventLazyLoading()` are process-wide settings that are fine to share. Run the suite with Octane's `--max-requests` set to a small value first.

### P2. Foreign keys without indexes on PostgreSQL (Low–Medium)

PostgreSQL does not index foreign keys automatically. The 2026-10-26 migration covered the hot paths, but these are still missing:

| Table.column | Used by |
|--------------|---------|
| `observations.tree_issue_id` | an issue's follow-up history; the `ON DELETE CASCADE` from `tree_issues` (a tree hard delete scans `observations` once per issue) |
| `observations.finding_id` | `Finding::isInUse()`, the `restrictOnDelete` check when a finding is deleted, records filters by finding |
| `tree_issues.finding_id` | `Finding::isInUse()`, `get_treatment_outcomes` with `finding`, `RecordRestorer::hasOtherOpenIssue()` |
| `oauth_access_tokens.client_id` | `AiConnections::revoke()`, client lookups during token validation |

**Recommendation:** add one migration with these four indexes (`observations (tree_issue_id)`, `observations (finding_id)`, `tree_issues (tree_id, finding_id)` to replace the single-column `tree_id` index, and `oauth_access_tokens (client_id)`). Extend the dataset in `QueryPlanTest` ("looking up rows by their foreign key uses an index") with these lookups.

### P3. `get_treatment_outcomes` hydrates every treated issue (Low)

`app/Mcp/Tools/GetTreatmentOutcomes.php` loads every issue that has a care record, together with its care records, and groups them in PHP. The tool is meant to be called before every treatment recommendation, and the data grows each season.

**Recommendation:** aggregate in SQL: join `tree_issues` → `care_record_tree_issue` → `care_records` → `findings`, `group by findings.name, trim(care_records.product)`, and compute `count(distinct tree_issues.id)`, the resolved count, and `avg(resolved_on - opened_on)` for resolved issues. The existing tests for the tool pin the output shape.

### P4. QR labels are regenerated on every visit (Low)

`OrchardController::qr` renders one BaconQrCode SVG per active tree each time the page loads. That is CPU-bound and grows with the number of trees (around 10–20 ms each for a few hundred trees).

**Recommendation:** cache each SVG by tree id (`Cache::rememberForever("tree-qr:{$tree->id}", …)`). The URL depends only on the tree id and `APP_URL`, so include `APP_URL` in the key, or clear the cache on deploy.

### P5. Sessions and cache on the database driver (Low)

`SESSION_DRIVER=database` and `CACHE_STORE=database`, so every request reads and updates a row in `sessions`. Rate limiting (login, passkeys, OAuth) also writes to `cache`. This is fine for a family-sized user base. It is the next bottleneck after P1 if traffic grows; Redis can then take sessions, cache and rate limiting.

### P6. Payload duplication (Low)

- `orchards.show` sends `trees` (full models), `activeTrees` (`id`, `code`) and `treeLayout`, which overlap. `activeTrees` can be derived on the client from `trees`.
- `HandleInertiaRequests::share()` still sends the full `User` model on every response (open since the last audit). Send only `id`, `name`, `email` and `is_owner`.

## What is already done well

- **Authentication:** Fortify with throttled login (email + IP) and passkeys. Production password policy requires 12+ characters, mixed case, symbols and the `uncompromised()` check. Emails are lowercased.
- **Deactivation** is enforced on every web and MCP request (`EnsureUserIsActive`), ends the session, and revokes OAuth tokens.
- **Seeding is safe on deploy:** `db:seed` runs on every start but creates the owner only once, and refuses the default password outside local and testing.
- **Authorization:** member management sits behind the `manage-members` gate, the owner cannot be deactivated, and revoking another user's AI connection checks the owner gate. All members have equal access to farm data, which is intentional for a family farm. Deletes are soft and can be restored from the trash.
- **Uploads:** at most 3 images of 8 MB each. Laravel's `image` rule excludes SVG. Files get generated names on a private disk, URLs are signed for 30 minutes, and Caddy's `X-Accel-Redirect` delivery was verified against `../` paths.
- **Injection:** every raw SQL fragment (`selectRaw`, `orderByRaw`, `whereRaw`) is static or uses bindings. The one `dangerouslySetInnerHTML` (QR labels) renders an SVG built from `route()`, not user input. `ReturnTo` only redirects to same-origin `/records/` URLs.
- **Configuration:** `APP_DEBUG=false` and `LOG_CHANNEL=stderr` are forced in `compose.yaml`, `expose_php=Off`, destructive DB commands are blocked in production, and `.dockerignore` keeps `.env`, keys and tests out of the image. No secrets are committed.
- **Performance groundwork:** composite indexes with query-plan tests, paginated records pages, partial reloads, deferred props, `preventLazyLoading()` outside production, and OPcache without timestamp validation.
