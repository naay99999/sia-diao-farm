# โครงเมนูเดสก์ท็อป หน้าภาพรวม และหน้าบันทึก — Design

วันที่: 2026-10-24
สถานะ: รออนุมัติ
เกี่ยวข้อง: `2026-10-24-product-direction-design.md` (หลักการ "เดสก์ท็อปเป็นหลัก" และเกณฑ์คัดฟีเจอร์), `2026-10-21-farm-mcp-design.md`, `2026-10-23-family-accounts-and-ai-page-design.md`

## เจตนาและเหตุผล

ตอนนี้แอปเก็บข้อมูลได้เยอะ แต่แทบไม่เอาข้อมูลนั้นกลับมาให้ดู เจ้าของจึงรู้สึกว่า "ทำได้แค่จดง่ายๆ ไปจดในแอปโน้ตก็ได้"

- เมนูมี 3 รายการ คือ สวน, ค่าใช้จ่าย และผู้ช่วย AI
- หน้าแรก `/` พาไปที่รายการสวนทันที ไม่มีภาพรวมของทั้งฟาร์ม
- "ต้องดูซ้ำ" และ "ปัญหาค้าง" ดูได้ทีละสวน
- การดูแลแสดงแค่ 10 รายการล่าสุดในหน้าสวน (`OrchardController::show`) ส่วนผลผลิต สภาพต้น และการขาย ไม่มีหน้ารายการรวม
- ถังขยะและการกู้คืนทำได้ผ่าน MCP เท่านั้น

งานนี้เพิ่ม 3 อย่าง ซึ่งข้อมูลส่วนใหญ่มีอยู่แล้ว

1. **ภาพรวม:** เปิดมาแล้วรู้ทันทีว่าแต่ละสวนเป็นอย่างไร
2. **หน้าบันทึก:** มีไว้ตรวจและแก้ข้อมูลที่จดเข้ามา โดยเฉพาะข้อมูลที่ Claude จด
3. **โครงเมนูใหม่:** รองรับหน้าวิเคราะห์และหน้าวางแผนที่จะทำในรอบหน้า

การค้นหาข้อมูลเก่า เช่น "พ่นยาอะไรไป กี่ลิตร กี่ขวด" ผู้ใช้จะถาม Claude ผ่าน MCP เป็นหลัก หน้าบันทึกจึงไม่ได้มีไว้ค้นหาเป็นหลัก

## Goals

### 1. ภาพรวม (หน้าแรกหลังล็อกอิน)

- `/` ของผู้ใช้ที่ล็อกอินแล้วพามาที่หน้าภาพรวม แทนรายการสวน
- แต่ละสวนมีสรุป 3 เรื่อง ผู้ใช้ยืนยันแล้วว่าต้องการครบทั้ง 3 เรื่อง
  1. **สุขภาพของสวน:** แสดงผังต้นและจำนวนต้นตามสถานะ
  2. **ฤดูนี้:** ผลผลิต (กก.) รายได้ (บาท) และค่าใช้จ่าย (บาท) ของรอบฤดูที่เปิดอยู่ ถ้าไม่มีรอบที่เปิดอยู่ให้บอกว่าไม่มี
  3. **ล่าสุดทำอะไรไป:** วันที่และชื่อยาหรือปุ๋ยของการใส่ปุ๋ยครั้งล่าสุด และของการพ่นยาครั้งล่าสุด
- รายการ "ต้องดูซ้ำ" และ "ปัญหาค้าง" ของทุกสวนรวมกัน แต่ละรายการบอกสวนและรหัสต้น และกดเข้าหน้าต้นได้ ให้ใช้ logic เดิมใน `IssueSummary` โดยทำให้ query ได้ทุกสวน
- บันทึกล่าสุดจาก Claude ใช้ `RecentAiRecords` ที่มีอยู่แล้ว

### 2. ผังต้น

- ตำแหน่งของต้นได้มาจากรหัสต้น ไม่ต้องเพิ่มช่องกรอก รหัสแบบ `A-05` แปลว่าแถว A ต้นที่ 5 ผู้ใช้ยืนยันแล้วว่าสวนจริงปลูกเป็นแถว และรหัสแบบนี้เข้าใจตรงกัน
- รูปแบบที่รับได้: ตัวอักษรหนึ่งตัวขึ้นไป ตามด้วย `-` หรือไม่มีก็ได้ แล้วตามด้วยตัวเลข เช่น `A-05`, `A5`, `AB-12` ตัวอักษรไม่สนตัวพิมพ์เล็ก/ใหญ่ ส่วนตัวเลขให้อ่านเป็นจำนวนเต็ม
- ต้นที่รหัสไม่เข้ารูปแบบ ให้วางรวมไว้ในแถวท้ายผังชื่อ "อื่นๆ" และเรียงตามรหัส
- สถานะของต้น ถ้าเข้าหลายข้อให้ใช้ข้อแรกที่เข้า
  1. **ถึงวันดูซ้ำ:** มีปัญหาเปิดอยู่ที่วันดูซ้ำมาถึงหรือเลยแล้ว
  2. **มีปัญหาค้าง:** มีปัญหาเปิดอยู่
  3. **ปกติ**
- ไม่แสดงต้นที่ตัดออกแล้ว (`removed_on`)
- กดที่ต้นแล้วเข้าหน้าต้น
- ผังเดียวกันนี้ต้องแสดงในหน้าสวนด้วย
- หน้าตาของผัง เช่น SVG, motion หรือ three.js ผู้ใช้จะกลับมาจัดการเองทีหลัง ในรอบนี้ให้ทำผังกริด SVG แบบเรียบตาม `DESIGN.md` แต่ต้องแยกข้อมูลผังออกจากส่วนที่วาด เพื่อให้เปลี่ยนวิธีวาดทีหลังได้โดยไม่ต้องแก้ backend

### 3. หน้าบันทึก

- มีแท็บแยกตามประเภท
  - การดูแล
  - สภาพต้น/ปัญหา (บันทึกสภาพต้นและการดูซ้ำ) แต่ละแถวเป็นบันทึกสภาพต้น ไม่แสดงปัญหา (`TreeIssue`) เป็นแถวของตัวเอง แต่บอกสถานะของปัญหาที่ผูกอยู่ (เปิดอยู่ / หายแล้ว) การแก้หรือลบปัญหาโดยตรงยังทำผ่าน MCP เท่านั้น เพราะแอปยังไม่มี route ของ `TreeIssue`
  - ผลผลิต
  - การขาย
  - ค่าใช้จ่าย
  - ถังขยะ
- แต่ละแท็บเป็นตารางที่เห็นรายการได้ครบ แบ่งหน้าได้ ไม่ได้ตัดเหลือ 10 รายการ
- ตัวกรอง
  - สวน
  - ช่วงวันที่ หรือรอบฤดู
  - คนที่จด (`created_by`)
  - ที่มาของบันทึก คือ Claude หรือแอป (`created_via`)
  - ใช้ตัวกรองเดียวกันทุกแท็บ ถ้าประเภทไหนกรองแบบใดไม่ได้ ให้ซ่อนตัวกรองนั้น
- แต่ละแถวแสดงป้ายบันทึกจาก AI และชื่อคนที่จด เหมือนป้ายที่หน้าต้น
- แก้ไขและลบได้จากแถว ใช้ route `update`/`destroy` และกฎเดิม เช่น การผูกการดูแลกับปัญหา
- มีปุ่มจดใหม่ในแต่ละแท็บ ใช้ฟอร์มและ route เดิม ซึ่งส่วนใหญ่ต้องเลือกสวนหรือต้นก่อน
- หน้าค่าใช้จ่ายเดิม (`/expenses`) ย้ายมาเป็นแท็บค่าใช้จ่าย และยังแสดงยอดรวมตามหมวดเหมือนเดิม URL เดิมต้อง redirect มาที่แท็บนี้
- **ถังขยะ:** แสดงบันทึกที่ลบแบบ soft delete จากทุกประเภท ได้แก่ การดูแล ผลผลิต สภาพต้น ปัญหา การขาย ค่าใช้จ่าย และโน้ต แต่ละรายการบอกวันที่ลบและกดกู้คืนได้ ยังไม่แสดงว่าใครเป็นคนลบ เพราะระบบไม่ได้เก็บข้อมูลนี้ (ไม่มี `deleted_by`) และรอบนี้ไม่เพิ่ม กฎการกู้คืนต้องเหมือน `RestoreRecord` ใน MCP ทุกข้อ เช่น ห้ามกู้ปัญหาถ้าต้นเดียวกันมีปัญหาเดียวกันเปิดอยู่แล้ว ให้ย้าย logic ไปไว้ที่เดียว แล้วให้ทั้งแอปและ MCP เรียกใช้

### 4. ตั้งค่า

- **บัญชีของฉัน:** โปรไฟล์และรหัสผ่าน มีอยู่แล้ว
- **สมาชิก:** มีอยู่แล้ว เข้าได้เฉพาะเจ้าของ
- **การเชื่อมต่อ Claude:** ย้ายส่วนตั้งค่า URL ของ MCP และรายการเชื่อมต่อของทุกคน มาจากหน้าผู้ช่วย AI ไว้ที่ `settings/ai`
  - ตอนนี้ route นี้ redirect ไป `/assistant` ให้เปลี่ยนเป็นหน้าจริง
  - ทุกคนเห็นและยกเลิกการเชื่อมต่อของตัวเองได้ ส่วนเจ้าของเห็นส่วนตั้งค่าและการเชื่อมต่อของทุกคน ใช้สิทธิ์เดิมใน `AssistantController::destroy`
  - หน้าผู้ช่วย AI เหลือแค่ส่วนสอนวิธีใช้ และบันทึกล่าสุดจาก Claude
- **รายการสิ่งที่พบ:** แสดงรายการแยกตามชนิด (ปัญหา / ระยะการเติบโต) แก้ชื่อได้ ลบได้เฉพาะรายการที่ยังไม่มีบันทึกใช้ และเพิ่มรายการใหม่ได้ ผู้ใช้ทุกคนจัดการได้ เพราะสมาชิกแก้ข้อมูลได้เท่าเจ้าของ

### 5. โครงเมนู

- **เดสก์ท็อป (sidebar):**
  1. ภาพรวม
  2. สวน
  3. บันทึก
  4. ผู้ช่วย AI
  5. ตั้งค่า
- ต้องเผื่อที่ให้ "วิเคราะห์" และ "วางแผน" ไว้หลัง "บันทึก" แต่ยังไม่ใส่ในเมนู
- **มือถือ (แถบล่าง):** ภาพรวม, สวน, ผู้ช่วย AI และบัญชี ส่วนหน้าบันทึกกับหน้าตั้งค่าเข้าได้จากหน้าบัญชี
- `mainNavItems` ใน `resources/js/lib/navigation.ts` ใช้ร่วมกันทั้งสองแบบ ต้องแยกให้กำหนดได้ว่าเมนูไหนแสดงบนอุปกรณ์ไหน

## Non-goals

- หน้าวิเคราะห์ (ผลการรักษา ผลผลิตเทียบหลายฤดู ต้นทุน) และหน้าวางแผน จะออกแบบแยกในรอบหน้า
- หน้าตาที่สวยขึ้นของผังต้น เช่น motion, three.js หรือ 3D ผู้ใช้จะทำเอง และห้ามเพิ่ม dependency ในรอบนี้
- ตำแหน่งต้นที่กรอกเอง ทิศของแถว หรือแผนที่จริงของสวน
- การรวมยอดปริมาณยาหรือปุ๋ย เพราะ `product` และ `quantity` ยังเป็นข้อความอิสระ ต้องรอฐานความรู้ปุ๋ย/ยา (roadmap ข้อ 3)
- หน้าโน้ตความรู้ โน้ตจะเห็นแค่ในถังขยะ ส่วนหน้าจัดการโน้ตอยู่ในกลุ่ม "ความรู้" รอบหลัง
- การรวมรายการสิ่งที่พบที่ซ้ำกัน เพราะต้องแก้ปัญหาที่เปิดซ้อนกันบนต้นเดียวกัน
- หมวดค่าใช้จ่ายที่แก้เองได้ ยังใช้ enum `ExpenseCategory` เหมือนเดิม
- การเปลี่ยนเครื่องมือ MCP นอกจากย้าย logic การกู้คืนไปไว้ที่เดียว

## Anti-goals

- หน้าภาพรวมโหลดช้า เพราะ query ต้นทีละต้นแบบ N+1 สถานะของทุกต้นต้องได้จาก query จำนวนคงที่
- เปิดหน้าบันทึกแล้วไม่รู้ว่ารายการไหน Claude จด หรือใครจด
- กู้คืนจากแอปได้ผลต่างจากกู้คืนผ่าน MCP
- ตารางบนมือถือล้นจอ หรือต้อง scroll แนวนอนทั้งหน้า ตามกฎใน `DESIGN.md` ตารางต้องเปลี่ยนเป็นแถวหรือการ์ด
- ลิงก์เดิม เช่น `/expenses`, `/orchards` หรือ QR `/t/{tree}` ใช้ไม่ได้
- สมาชิกเข้าหน้าสมาชิกได้ หรือเห็นการเชื่อมต่อของคนอื่น

## ข้อจำกัด

- ข้อความที่ผู้ใช้เห็นเป็นภาษาไทยทั้งหมด รวม `aria-label` และ `sr-only`
- UI ทำตาม `DESIGN.md` แบบเดสก์ท็อปเป็นหลัก และใช้ component ที่มีอยู่ เช่น `Heading`, `SectionTabs`, `EmptyState`, `Badge` และ `useConfirm`
- ห้ามเพิ่ม dependency
- ทุกการเปลี่ยนแปลงต้องมี Pest feature test ทั้ง props ของหน้าใหม่ ตัวกรอง การกู้คืน สิทธิ์ และ redirect
- ใช้ Wayfinder สำหรับ route ฝั่ง frontend

## สิ่งที่ปล่อยให้คนทำตัดสินใจ

- ชื่อ route และ URL ของหน้าใหม่ เช่น `/overview` และ `/records/{type}`
- ค่าใช้จ่ายที่ไม่ได้ผูกกับรอบฤดูจะแสดงอย่างไรเมื่อกรองตามสวน
- บันทึกที่อยู่ในถังขยะนับว่า "ยังใช้" รายการสิ่งที่พบอยู่หรือไม่ ตอนลบรายการนั้น
- จำนวนรายการต่อหน้า
- จะแสดงผังของทุกสวนในหน้าภาพรวมพร้อมกัน หรือให้เลือกทีละสวน ให้เลือกตามจำนวนสวนและความกว้างจอ
- โครงสร้างของ class ฝั่ง backend ที่ใช้คำนวณภาพรวมและผังต้น

## การตัดสินใจของผม (ผู้ใช้ยังไม่ได้ยืนยันทีละข้อ)

- ใช้รหัสต้นเป็นตำแหน่งบนผัง และวางต้นที่รหัสไม่เข้ารูปแบบไว้ในแถว "อื่นๆ"
- ลำดับสถานะ ถึงวันดูซ้ำ > มีปัญหาค้าง > ปกติ
- ย้ายส่วนการเชื่อมต่อ Claude ไปไว้ที่ `settings/ai`
- รายการสิ่งที่พบทำได้แค่แก้ชื่อ ลบรายการที่ไม่ได้ใช้ และเพิ่มใหม่ ยังไม่รวมรายการ
- แถบล่างบนมือถือมี 4 ช่อง และหน้าบันทึกกับหน้าตั้งค่าเข้าจากหน้าบัญชี
- ถังขยะไม่แสดงว่าใครเป็นคนลบ และรอบนี้ไม่เพิ่มคอลัมน์ `deleted_by` จึงไม่มีงานแก้ schema
- แท็บสภาพต้น/ปัญหาแสดงแค่บันทึกสภาพต้น และไม่เพิ่ม route สำหรับแก้หรือลบ `TreeIssue`
