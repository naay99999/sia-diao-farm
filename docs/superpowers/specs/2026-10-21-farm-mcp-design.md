# MCP สำหรับสวน (ผู้ช่วย AI ผ่าน Claude) — Design

วันที่: 2026-10-21
สถานะ: รออนุมัติ
เกี่ยวข้อง: `2026-10-21-tree-observations-design.md` (ข้อ 1) และข้อ 2–5 ของแผนรวม (แผนงาน, คลังปุ๋ย/ยา, รวมค่าใช้จ่าย, เกรดผลผลิต) ที่ยังไม่ได้เขียน spec

## Intent และเหตุผล

ผู้ใช้มีสองคน คือเจ้าของสวนและคนดูแลสวน ใช้มือถือเป็นหลัก และบันทึกงานช่วงเย็น เป้าหมายคือ "เก็บข้อมูลเยอะ แต่กรอกง่าย" และอยากได้ผู้ช่วยที่แนะนำเรื่องปุ๋ยและยาได้

แทนที่จะสร้าง AI ในแอปเอง จะเปิดข้อมูลของแอปเป็น **MCP server** ให้ Claude ของเจ้าของ (บน claude.ai และแอปมือถือ) ต่อเข้ามาอ่านและเขียนข้อมูลได้ ผลที่ได้คือ:

- ไม่มีค่า AI API และไม่ต้องดูแลโค้ด AI ฝั่งเรา
- ได้ทั้งการพูดแทนพิมพ์ การดูรูป การถามตอบ และการค้นเว็บ จากความสามารถที่ Claude มีอยู่แล้ว
- ผู้ช่วยเก่งขึ้นเองเมื่อโมเดลพัฒนา

เหตุผลที่เลือก Claude: ณ ต.ค. 2026 แอป Gemini เปิดให้เพิ่ม MCP เองได้เฉพาะในสหรัฐฯ และภาษาอังกฤษ ส่วน ChatGPT ใช้ได้บนเว็บเท่านั้น และอาจเขียนข้อมูลได้เฉพาะบางแพ็กเกจ Claude เพิ่ม connector บนเว็บครั้งเดียวแล้วใช้บนมือถือได้ ผู้ใช้ยืนยันแล้วว่าเจ้าของจะเปลี่ยนมาใช้ Claude ส่วน MCP ควรทำตามมาตรฐาน เพื่อให้ client อื่นต่อได้ในอนาคต

**แบ่งหน้าที่:** แอปเก็บข้อมูลที่มีโครงสร้างและเป็นเจ้าของกฎความปลอดภัย Claude ทำหน้าที่คุย อธิบาย แนะนำ และช่วยบันทึก

## Goals

1. **อ่านข้อมูลได้ครบ:** สวน ต้น ฤดูกาล บันทึกการดูแล สภาพต้นและปัญหา (รวมการดูซ้ำ) ผลผลิต การขาย ค่าใช้จ่าย คลังปุ๋ย/ยา (เมื่อข้อ 3 เสร็จ) และโน้ตความรู้ของสวน ต้องค้นด้วยรหัสต้น เช่น "B3" ได้ และกรองตามช่วงวันที่หรือฤดูกาลได้
2. **เขียนข้อมูลได้:** สร้าง แก้ และลบ บันทึกการดูแล สภาพต้น การดูซ้ำ ผลผลิต การขาย ค่าใช้จ่าย และโน้ตความรู้ (รวมแผนงานเมื่อข้อ 2 เสร็จ) โดยใช้ business rule เดียวกับในแอป เช่น ผูกการดูแลกับปัญหา และวันดูซ้ำ +7 วัน ตาม spec ข้อ 1
3. **ทวนก่อนบันทึก:** ทุกการเขียน แก้ และลบ Claude ต้องทวนสรุปในแชตให้ผู้ใช้ยืนยันก่อน แล้วบันทึกลงระบบทันที ไม่มีขั้นร่างในแอป
4. **ตรวจสอบย้อนหลังได้:** ทุกบันทึกเก็บว่ามาจากแอปหรือจาก MCP และผู้ใช้คนไหนเป็นคนทำ หน้าแอปแสดงป้ายเล็กๆ ว่าบันทึกนี้มาจาก AI
5. **ลบแล้วกู้คืนได้:** การลบจากทุกช่องทางเป็น soft delete และกู้คืนได้ในแอป
6. **ผลจริงของสวน:** มีเครื่องมือสรุปว่าการรักษาแต่ละแบบได้ผลแค่ไหน เช่น "ยา X กับไรแดง: ใช้ 5 ครั้ง หาย 4 ครั้ง ใช้เวลาเฉลี่ย 9 วัน" คำนวณจากปัญหา การดูแลที่ผูกไว้ และผลการดูซ้ำ (ข้อ 1)
7. **โน้ตความรู้ของสวน:** ผู้ใช้พูดในแชตได้ว่า "จำไว้ว่า..." แล้ว Claude บันทึกเป็นโน้ต โน้ตผูกกับหัวข้อได้แบบไม่บังคับ (ปัญหา ยา/ปุ๋ย ระยะการเติบโต หรือต้น) ดูและแก้ในแอปได้ด้วย
8. **กฎความปลอดภัยเป็นข้อเท็จจริงจากฝั่งเรา:** ระยะปลอดสารก่อนเก็บเกี่ยว การหมุนกลุ่มยา และอัตราการใช้ตามฉลาก ให้ server คำนวณแล้วส่งผลออกไป เช่น "ต้นนี้ใช้ยากลุ่ม 6 มา 3 ครั้งติดแล้ว" หรือ "ยานี้ระยะปลอดสาร 14 วัน แต่ฤดูกาลนี้คาดว่าจะตัดในอีก 10 วัน" ห้ามให้ AI คิดเอง (ข้อนี้ต้องรอข้อมูลจากคลังปุ๋ย/ยาในข้อ 3)
9. **คำสั่งให้ Claude:** instructions ของ server บอกลำดับแหล่งความรู้ที่ต้องใช้ตอนแนะนำ
   1. กฎความปลอดภัยจากระบบ ห้ามขัด
   2. ผลจริงของสวน
   3. โน้ตความรู้ของเจ้าของ
   4. ข้อมูลจากเว็บ

   และบอกว่า: ทวนก่อนเขียนทุกครั้ง, ตอบเป็นภาษาไทย, อ้างอิงต้นด้วยรหัส, ห้ามแต่งอัตราการใช้ยาขึ้นเอง
10. **ล็อกอิน:** OAuth 2.1 ผ่าน Laravel Passport และ `Mcp::oauthRoutes()` ตามเอกสาร `laravel/mcp` แต่ละคนล็อกอินด้วยบัญชีแอปของตัวเอง

## Non-goals

- AI ที่สร้างเองในแอป, ค่า AI API ฝั่งเรา และ Telegram/LINE bot (ตัดออกจากแผนแล้ว)
- การแจ้งเตือนเชิงรุก เพราะ MCP ทำงานเฉพาะตอนที่ผู้ใช้เปิดคุย การเตือนยังใช้รายการ "ต้องดูซ้ำ" ในแอปเหมือนเดิม
- การปรับให้เข้ากับ Gemini หรือ ChatGPT โดยเฉพาะ
- ระบบสิทธิ์หลายระดับ ผู้ใช้ทุกคนเห็นและแก้ข้อมูลทุกสวนได้เหมือนในแอปตอนนี้
- AI วิเคราะห์รูปฝั่งเรา (Claude ดูรูปในแชตเอง)

## Anti-goals

- AI เขียน แก้ หรือลบข้อมูลโดยไม่ทวนกับผู้ใช้ก่อน หรือทำแล้วย้อนกลับไม่ได้
- AI ให้อัตราการใช้ยาหรือระยะปลอดสารที่ไม่ได้มาจากข้อมูลในระบบ
- ข้อมูลที่เขียนผ่าน MCP ผิด rule ที่แอปบังคับใช้ เช่น ข้าม validation หรือข้ามการผูกปัญหา
- เครื่องมือเยอะหรือคืนข้อมูลก้อนใหญ่เกินไป จน Claude เลือกเครื่องมือผิด หรือ context เต็ม
- MCP เปิดออกอินเทอร์เน็ตโดยไม่มีการล็อกอิน

## Constraints

- ใช้ `laravel/mcp` ซึ่งตอนนี้มีอยู่แค่ในฐานะ dependency ของ `laravel/boost` (require-dev) ต้องย้ายมาไว้ใน `require` ก่อน เป็น web server (Streamable HTTP) เส้นทางอยู่ใน `routes/ai.php`
- ผู้ใช้ **อนุมัติแล้ว** ให้เพิ่ม `laravel/passport` และย้าย `laravel/mcp` มาไว้ใน `require`
- Deploy: ผู้ใช้จะ deploy ด้วย Docker บน VPS ต้องมีโดเมนและ HTTPS สาธารณะ ให้ `APP_URL` ชี้ไปที่โดเมนนั้น และต้องมี Passport keys ใน production งานตั้งค่า Docker/VPS **แยกเป็นงานอีกชิ้น ไม่อยู่ในแผนนี้** แต่ MCP ต้องรอให้ deploy เสร็จก่อนถึงจะทดสอบกับ Claude จริงได้ ส่วนในแผนนี้ให้ทดสอบด้วย feature test ส่วน route สำหรับลงทะเบียน client ต้องมี rate limit
- **business logic ต้องใช้ร่วมกันระหว่าง controller กับ MCP tool** เช่น action/service class หรือ Form Request rule ร่วม เพื่อไม่ให้มีสองที่ที่บังคับ rule ต่างกัน ข้อนี้น่าจะต้อง refactor controller เดิมบางส่วน
- ข้อความ error และ validation ที่ส่งกลับ ต้องชัดพอให้ AI แก้แล้วลองใหม่ได้ (ตามแนวทางของ `laravel/mcp`)
- ใช้ tool annotation ให้ถูกต้อง: `IsReadOnly` สำหรับเครื่องมืออ่าน และ `IsDestructive` สำหรับลบ
- ต้องมี feature test ของทุก tool รวมถึงการล็อกอิน
- ข้อความที่ผู้ใช้เห็นเป็นภาษาไทย ส่วนชื่อ tool, schema และคำอธิบาย tool เขียนเป็นภาษาอังกฤษได้ เพราะ AI อ่านภาษาอังกฤษได้ดี แต่ต้องตอบผู้ใช้เป็นภาษาไทย

## ลำดับการทำ (ขึ้นกับ spec อื่น)

1. **ระยะ A:** OAuth, การบันทึกที่มาและผู้ทำ, soft delete, เครื่องมืออ่านและเขียนข้อมูลที่มีอยู่แล้ว (สวน ต้น ฤดูกาล การดูแล ผลผลิต การขาย ค่าใช้จ่าย) และโน้ตความรู้
2. **ระยะ B (หลังข้อ 1):** สภาพต้น ปัญหา การดูซ้ำ และเครื่องมือสรุปผลจริงของสวน
3. **ระยะ C (หลังข้อ 3):** คลังปุ๋ย/ยา และกฎความปลอดภัย (ระยะปลอดสาร กลุ่มยา อัตราการใช้)
4. **ระยะ D (หลังข้อ 2):** แผนงาน

## สิ่งที่ตัดสินใจแล้ว

| เรื่อง | การตัดสินใจ | มาจาก |
|---|---|---|
| ใช้ MCP แทนสร้าง AI ในแอป | ใช่ | ผู้ใช้ |
| AI client หลัก | Claude (เจ้าของจะเปลี่ยนมาใช้) | ผู้ใช้ |
| การเขียนข้อมูล | ทวนในแชตก่อน แล้วบันทึกทันที | ผู้ใช้ |
| แก้และลบ | ทำได้ แต่ต้องทวนในแชตก่อน | ผู้ใช้ |
| แหล่งความรู้ | ประสบการณ์ของเจ้าของ, คนขายที่ร้าน, เว็บ (เก็บเป็นผลจริงของสวน, โน้ตความรู้, หมายเหตุในคลังยา และให้ Claude ค้นเว็บเอง) | ผู้ใช้ยืนยัน |
| ลำดับความน่าเชื่อถือของความรู้ | กฎความปลอดภัย → ผลจริง → โน้ต → เว็บ | ผู้ใช้ยืนยัน |
| เก็บที่มาและผู้ทำ | ใช่ และแสดงป้ายในแอป | Claude |
| soft delete | ใช่ ทุกช่องทาง | Claude |
| ล็อกอิน | OAuth ผ่าน Passport | Claude (ตามคำแนะนำของ laravel/mcp) |
| ขอบเขตของ soft delete | เฉพาะบันทึกที่ MCP เขียนได้ ได้แก่ การดูแล สภาพต้นและปัญหา การดูซ้ำ ผลผลิต การขาย ค่าใช้จ่าย และโน้ต ส่วนสวน ต้น และฤดูกาล ยังใช้การลบแบบเดิม | Claude |
| การเก็บที่มา | เก็บทั้งผู้สร้าง/ช่องทางที่สร้าง และผู้แก้/ช่องทางที่แก้ล่าสุด ป้ายในแอปแสดง "บันทึกโดย AI" หรือ "แก้โดย AI" ตามจริง ไม่ทำ change log เต็ม | Claude |
| ลำดับการสร้าง | ทำข้อ 1 (สภาพต้น) ให้เสร็จก่อน แล้วค่อยวางแผน MCP ระยะ A+B พร้อมกัน เพื่อให้ action ที่ใช้ร่วมกันออกแบบรอบเดียว | Claude |

## ให้ผู้สร้างตัดสินใจเอง

- ชุดเครื่องมือ: ชื่อ ขอบเขต จำนวน (ควรรวมให้น้อยและชัด เช่น `search_trees`, `get_tree`, `list_open_issues`, `log_care`, `log_observation`) รวมถึงจะใช้ resource หรือ prompt ของ MCP ด้วยไหม
- รูปแบบข้อมูลที่ส่งกลับ และการแบ่งหน้า (pagination)
- โครงสร้างของ action/service ที่ใช้ร่วมกัน
- schema ของโน้ตความรู้ การเก็บที่มาและผู้ทำ และ soft delete
- หน้าแอปสำหรับดูโน้ตความรู้และกู้คืนสิ่งที่ลบ (ทำให้เรียบง่ายตาม DESIGN.md)
- รูปถ่ายผ่าน MCP: ถ้า Claude ส่งไฟล์รูปผ่าน tool ได้จริง ให้รองรับการแนบรูป ถ้าไม่ได้ ให้รูปยังอัปโหลดผ่านแอปเท่านั้น
